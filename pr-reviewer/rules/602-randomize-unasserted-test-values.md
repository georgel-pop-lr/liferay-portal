# 602: Randomize Test Values You Do Not Assert

Examine every hardcoded string and number in a test. If no assertion checks its value, replace it with `RandomTestUtil` (`randomString`, `randomLong`, and so on). This covers URLs, file names, IDs, names, exception messages, and JSON field values passed into setup, construction, a mock, or a builder — anything the test only passes through and never asserts on. Keep a hardcoded literal only for a value the test actually checks or that the implementation requires — for example, the only enum value an endpoint accepts, or a field whose absence would cause the call to fail. Repeat a fixed literal the test checks at every place it is set and asserted, even across test methods, rather than naming a constant for it. A constant is for a value the test cannot repeat inline, a `RandomTestUtil` value shared between the setup and the assertions.

A value is checked when an assertion checks it or any rendering of it, not only when the assertion names it verbatim. A usage count stubbed as `3` and asserted as `"3"` is checked, because the assertion fails for every other count, so the exemption above applies and the literal stays. Randomizing it would force the expected side to be recomputed from the input, as `Assert.assertEquals(String.valueOf(usageCount), ...)`, and this codebase does not do that: counted over the test sources of `modules/apps` on 2026-09-23, 2,482 `Assert.assertEquals` calls take a bare string literal as the expected argument against 3 that wrap it in `String.valueOf`. A sibling test that randomizes the same kind of value is not evidence against this, since it is the assertion that decides, not the value's name: in `BasicFragmentEntryActionDropdownItemsProviderTest` the count is randomized because only the `disabled` flag is asserted, while in `BasicFragmentEntryVerticalCardTest` the same count is the subtitle under test.

**Rationale:** A hardcoded literal signals that the exact value matters. When it does not, the literal misleads the reader into looking for a significance that is not there. A random value proves the test does not depend on it and surfaces any accidental coupling to a specific input.

A violation is any hardcoded string or number in a test that no assertion depends on and that the implementation does not require, where `RandomTestUtil` should be used. Before flagging a hardcoded non-asserted value, verify with `git grep --cached` against the implementation that the value is not required. Examples: a URL or file name passed to a mock or a builder, an exception message in `new SomeException("Some error")`, a folder name in `addFolder("Test Folder")`, a portal URL the test never checks, or a JSON `"message"` value when the test only asserts a flag such as `isQuotaExceeded()`. The related violation is a random value the test needs in more than one place, generated inline at each one instead of stored once in a named constant or local. A fixed literal repeated across the setup and the assertions is not a violation: counted over the `*Test.java` sources of `modules/apps` outside Commerce on 2026-10-08, 3,080 `Assert.assertEquals` calls take as the expected argument a string literal that appears again in the same file, in 600 files, against 327 that assert a `private static final String` constant holding a fixed literal, in 78 files. On LPD-103742 Shared request race during full reindex breaks layout rendering and silently drops page content from the index (https://liferay.atlassian.net/browse/LPD-103742), the liferay review asked three rounds running for `"/a.jsp"`, `"/b.jsp"`, `"/outer.jsp"` and `"head"` in `LayoutServiceContextHelperTest` to become constants, and the finding was refused each time.

**Example:** commit `5df4f1a` replaced `"Test Folder"` with `RandomTestUtil.randomString()`; `1b0e932` replaced fixed file names with `randomString()`; `8dcff7c` replaced the fixed `"longDescription"`, `"detailURL"` and `"title"` with the constants `_DESCRIPTION`, `_LINK` and `_TITLE`, each holding `RandomTestUtil.randomString()`, under the title "Make it obvious it's random": the constant exists because the value became random, not because it repeated.
