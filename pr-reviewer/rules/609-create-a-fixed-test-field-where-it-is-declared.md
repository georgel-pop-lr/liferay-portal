# 609: Create a Fixed Test Field Where It Is Declared

A test's instance field whose value needs nothing from the setup is created in its declaration as a `private final` field, not declared bare and assigned in `@Before`. That covers a plain `Mockito.mock(Foo.class)`, a `new MockHttpServletRequest()`, and any other constructor that takes no value the setup produces. JUnit builds a fresh instance of the test class for every test method, so the initializer runs once per test exactly as the `setUp` assignment did, and the field can be `final` because nothing assigns it again.

`@Before` is then left to the work that really needs a method: stubbing a mock, wiring one fixture into another (`_mockHttpServletRequest.setAttribute(WebKeys.THEME_DISPLAY, _themeDisplay)`), opening a `MockedStatic` stub, and building a value that depends on setup done before it.

This rule does not apply to a field whose value depends on earlier setup (a static utility that has to be registered first, a value computed from another field in `setUp`), a field some test reassigns, a fixture that needs the running portal such as `GroupTestUtil.addGroup()` in an integration test, which stays in `@Before` beside `@DeleteAfterTestRun`, or a field filled by `@Inject` or `@Mock`. Static fields are outside it too; a `MockedStatic` held in a static field and closed in `@AfterClass` is its own shape.

**Rationale:** A bare declaration plus an assignment in `setUp` spends two places and a line of setup on a value that never varies, and it hides the setup that does matter among lines that are pure construction. Counted over the test sources in `modules/apps` outside Commerce on 2026-09-26, 992 instance fields holding a plain `Mockito.mock(Foo.class)` or `new Mock*()` are initialized in their declaration, across 303 files, against 89 declared bare and assigned in `setUp()`, across 50 files. Of the fields initialized in the declaration, 961 are `private final` against 5 that are not.

A violation is an added or modified instance field in a test that is declared without a value and assigned in `@Before` to a value that needs nothing from the setup, or such a field initialized in its declaration without `final`.

**Example:** on LPD-105566 Use the design library group when adding a page from its page template set (https://liferay.atlassian.net/browse/LPD-105566), Brian Chan closed https://github.com/brianchandotcom/liferay-portal/pull/182430 with "class level declare these ... don't waste space in the set up" (https://github.com/brianchandotcom/liferay-portal/pull/182430#issuecomment-5836850839) against `SelectLayoutPageTemplateEntryDisplayContextTest.setUp`, which assigned `_layoutPageTemplateCollection = Mockito.mock(LayoutPageTemplateCollection.class)`, `_themeDisplay = Mockito.mock(ThemeDisplay.class)` and `_mockHttpServletRequest = new MockHttpServletRequest()` to bare fields. All three became `private final` fields created where they are declared, leaving `setUp` with the `MockedStatic` stub and the `setAttribute` call. `ProductMenuDisplayContextTest` in `product-navigation-product-menu-api` already declares the same pair this way, `_mockHttpServletRequest` at line 159 and `_themeDisplay` at line 170.
