# 603: Name a Test Method After the Method It Tests

Name a test method `test` followed by the exact name of the method it tests, including that method's own `is` or `has` prefix. The test for `isQuotaExceeded()` is `testIsQuotaExceeded`, not `testQuotaExceeded`; the test for `isValidConnection()` is `testIsValidConnection`. Append a scenario qualifier for a variant, as in `testIsValidConnectionWithNullAPIKey`.

The method it tests is one the subject declares, the subject being the class the test is named after with its `Test` suffix removed, and that holds however the test reaches it. An integration test that drives the subject through the runtime instead of calling it still takes its name from the method under test, with the flow it drives written into the qualifier. When the subject declares a single public method, every test method in the class begins with that method's name.

**Rationale:** A test name that matches the method under test lets a reader jump from a failing test straight to the method, and it keeps the suite's names parallel to the API. Dropping the `is`, writing `testQuotaExceeded` for `isQuotaExceeded`, breaks that mapping and hides which method the test covers. Naming a test after the scenario breaks it outright, because nothing in the name says which method the failure belongs to and the class stops reading as a list of the methods it covers.

A violation is a test method whose name does not begin with `test` plus a method the subject declares. It takes two common forms: a name that omits the `is` or `has` prefix of the method under test, and a name taken from the behavior or the flow the test drives rather than from any method on the subject.

**Example:** https://github.com/brianchandotcom/liferay-portal/pull/181681 was closed with "test method names do not map to name being tested". `LayoutPageTemplateDepotRolePermissionsContributor` declares one public method, `getDepotRolePermissions()`, and its integration test named its methods after the flow they drove, `testManageLayoutPageTemplatesWithDesignLibraryMember` and `testManageLayoutPageTemplatesWithDesignLibraryRoles`. The names are `testGetDepotRolePermissionsWithDesignLibraryMember` and `testGetDepotRolePermissionsWithDesignLibraryRoles`, which keep the scenario in the qualifier. The unit test in the same pull, `testGetDepotRolePermissions`, already mapped.
