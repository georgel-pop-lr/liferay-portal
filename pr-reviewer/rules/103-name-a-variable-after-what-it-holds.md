# 103: Name a Variable After What It Holds

Name a variable after the type or content it holds, not after an incidental role. A `JSONObject` is `jsonObject`; a `String` that holds JSON ends in `JSON`, as in `objectDefinitionJSON`; a `Page` ends in `Page`. Count the values of a type that the method itself uses, not every one in scope. When the method holds one, the plain type name is enough (`enumeration`, `file`, `pageElementResource`), because the method's own name already says what the value is for: in `_testGetSitePageExperienceWithoutPreviewDraftPermission`, the client built for a user without the permission is `pageExperienceResource`, not `userPageExperienceResource`. A field the method never reads does not count, and neither does a value a later test might add. Add a qualifier only when the method holds a second value of the type, and then keep it short and take it from the codebase, as `userPageExperienceResource`, not `userWithoutPermissionsPageExperienceResource`.

An inherited field the method reads is that second value only when the local would take the field's own name and shadow it. A `*ResourceTest` inherits the administrator's client, `pageExperienceResource`, from its generated base class, so a method that calls it and then declares a client for another user under the same name shadows it, and every line after the declaration silently changes user. Qualify the local there. Counted over the `*ResourceTest.java` files in `modules/apps` outside Commerce, on `upstream/master` at `24cdfc6d52a83`: of the locals holding a REST client `*Resource` in a method that uses no other value of that type, 219 take the plain name and 49 a qualifier. Where the method also reads the inherited field, 26 qualify the local and 19 shadow the field, which is close, so suggest the qualifier there but do not report its absence as a violation. Among the qualified locals declared on one line, `user` is the prefix 19 times out of 54, the next most common, `siteMember`, 4 times, and `userWithoutPermissions` twice.

A field with a different name is not shadowed, so it does not count. A `Group` local next to the inherited `testGroup` or a `_group` field takes the plain name `group`. Counted over the `*Test.java` files on `upstream/master` at `2906387d50ce4`, since 2024: Brian Chan renamed a qualified `Group` local to `group` 15 times in 4 commits, and never the other way. In `015196d35dfdb` LPD-17648 Rename, `testGroup2` became `group` in `SearchResultResourceTest._testPostSearchPageWithGroupERCAndIdScope`, a method that also reads `testGroup`. In `a8bfbeb5de6dd` LPD-91396 as used/SF, `scopeGroup` became `group` in a method that also reads `_group`. On LPD-108819 Resolve a page's master page in its scope group (https://liferay.atlassian.net/browse/LPD-108819), a review asked to rename `group` to `depotGroup` in `SitePageResourceTest._testGetSiteSitePageWithDesignLibraryMasterPage` because the method reads `testGroup`. The rename went the other way.

A DTO field is that second value too, inside the double-brace initializer of an anonymous subclass. In `new MasterPage() {{ setName(name); }}` the inherited `protected String name` field hides the local, so the setter passes the field to itself and the local is never read. Qualify the local that a double-brace setter reads (`masterPageName`), and do not report the qualifier as a violation. Counted over the `*Test.java` files in `modules/apps/headless` on `brian/master` at `318e9227de210`: of the double-brace setters whose argument is a local named after the field, 9 qualify it and 0 take the plain field name. On LPD-108811 Serve master pages at Design Library scope (https://liferay.atlassian.net/browse/LPD-108811), a review asked to rename `masterPageName` in `MasterPageResourceTest.testPatchDesignLibraryMasterPage` to `name`, which would have sent a null name.

A collection takes the plural and needs no type suffix on its own: `String userName` pairs with `String[] userNames`. Add an `...Array` or `...List` suffix only to break a tie, when the same content is held in two collection types in the same scope, such as a `String[]` and a `List<String>` of the same thing. Then suffix to tell them apart, as `userNamesArray` with `userNamesList`, or leave one as the plain plural and suffix the other, and stay consistent across the class. A plain plural array such as `requestBlacklistItems` is correct on its own.

**Rationale:** A name that states the type tells the reader what they are handling without tracing back to the declaration, and it keeps similar variables named the same way across the codebase. A name taken from an incidental role (`metadata`, `userValue`, `result`) hides the type and invites a mismatch between the name and what the value actually is. The collection suffix earns its place only when it resolves a real ambiguity, so adding `Array` to an array that has no `List` twin is the redundant noise this naming avoids.

A violation is a variable named for an incidental role rather than its type or content, or a name whose stated type does not match what it holds: a `String` of JSON named `objectDefinitionString` rather than `objectDefinitionJSON`, or a collection named as if it held a single element. A plural array without an `...Array` suffix is not a violation unless another collection of the same content shares its name. A qualifier on a variable whose method holds no second value of its type is a violation too, such as `userWithoutPermissionsPageElementResource` in a helper that never reads the inherited `pageElementResource`, or `postPageElement` and `getPageExperience` in a method with one `PageElement` or one `PageExperience`.

**Example:** commit `a8af2ca` renamed `metadataJSONObject` to `jsonObject`; `ec36099` renamed `objectDefinitionString` to `objectDefinitionJSON` because it holds JSON; `84d9629` renamed `getAgentDefinitions` to `getAgentDefinitionsPage` because it returns a `Page`; `320d3dc` renamed the vague `result` to `json`, the JSON that `getJSON` returns.

**Example:** on LPD-107120 Page element endpoints resolve the page through LayoutLocalService without a VIEW permission check (https://liferay.atlassian.net/browse/LPD-107120), Georgel Pop renamed `userWithoutPermissionsPageElementResource`, `userPageExperienceResource`, `draftSegmentsExperience`, `postPageElement`, and `getPageExperience` to the plain type names in the `headless-admin-site-test` helpers that held one value of each type. The same pass left two methods that read the inherited client before declaring the other user's under the same name, `testGetSitePageSpecificationPageExperiencePageElement` in `PageElementResourceTest` and `testGetSitePageExperience` in `PageExperienceResourceTest`, which is where `userPageElementResource` and `userPageExperienceResource` still belong.
